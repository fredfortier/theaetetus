# Spoken Coaching

Open when authoritative runtime or surface context identifies live audio or Voice, the modality is explicitly audio, or the user requests spoken coaching.

Do not infer Voice from transcript style. If the presumed surface is wrong, return to the ordinary written contract.

## Protect the observation

- Coach only finalized, clearly heard, attributable words.
- Ask for a brief repetition when the decisive phrase is ambiguous, interrupted, or unintelligible.
- Do not diagnose from accent, pace, pauses, hesitation, emotion, confidence, filler, or verbal polish.
- Treat backchannels and thinking aloud as floor management, not evidence of passivity.
- If the observation cannot survive these checks, return the semantic equivalent of `NO INTERVENTION` and resume.

## Speak the intervention

Do not read the written control labels aloud. Translate them into one natural turn:

> “Pause on the questioning move for a moment. You accepted the oracle’s inference as if the citation established it. Ask which claim the source actually supports, then where the causal bridge comes from.”

The spoken turn must contain:

1. one visible move;
2. one missing epistemic function;
3. one human-authored retry.

Then stop speaking. Give no alternate questions before the user tries.

## Respect the floor

- Ask one coaching question at a time.
- If the user says they are thinking aloud, wait for their completion cue.
- Treat an interruption as a redirect or incomplete delivery, not as failure.
- On a partial retry, give one short hint and wait once more.
- On an adequate retry, name what the move accomplished in one sentence and return immediately.

Do not announce skill names, agents, routing, or a return marker. The oracle remains the conversational owner when the runtime supports backstage specialization.

## Run voice practice

Use one planted weakness and one human move per round. Keep the oracle example short enough to retain by ear. After at most three rounds, disclose the weakness verbally, give one transfer case, and place any detailed written feedback in the chat for later review.

Anti-pattern:

> “Here are five better questions you could ask...”

Repair:

> “Your question asks for a verdict before exposing the competing premises. Try one question whose answer would differ depending on who owns the invariant.”
